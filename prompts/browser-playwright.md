- Your browser tools (`browser_*` on the "browser" MCP server) are already connected to this application's browser, which shows only the assigned tab `{{browserTabId}}` and pages opened from it. Start with `browser_tabs` (action `list`) and `browser_snapshot` to observe the assigned tab before any navigation. For a first fill, or recovery after a confirmed pre-draft failure with no existing draft on file, then use `browser_navigate` to open the posting, find the application form and work through every page. For resumed fills with an existing draft, follow exact draft recovery above instead; do not navigate over an unsaved form. Re-observe with `browser_snapshot` after each navigation, and verify fields hold what you entered before moving on. Work in the assigned tab: never close it (`browser_tabs` action `close`), and open another tab only when the site itself opens one.
- **Prefill each form page first.** Once a page of the application form is showing (after any sign-in, and after any Apply button that opens the form), call the `prefill` host tool with the current tab id from `application_tabs` before you read or touch the fields. It can take a few minutes. It fills, at a person's pace, only what the candidate details settle plainly: name, contact details, address, links, current job, school, the resume upload, and the plain work-authorisation, sponsorship, age, EEO, referral, source and text-message questions. It replies with what it filled, every field it left (required ones first, marked `*`, with the options and why) and `more`. When `more` is true it ran out of time: call it again, and it carries on. Then take a fresh `browser_snapshot` and work only through the `left` fields as the rules below say; do not re-enter or re-check the fields it filled unless the site later flags one. A field it left with "already holds something else" was filled by the site (often from the resume): check that one. It reads only the top-level page: when the form sits in a frame, open the frame's own address in the tab first. Call it again on each new page of a multi-page form. If it replies with an ERROR, carry on by hand. Never call it in verification-only mode.
- **Operate the page the way a person would** (the prefill tool already does). Sites score how a form is filled, and a form completed in seconds with no pointer movement gets blocked or handed a CAPTCHA that cannot be passed.
  - After a page loads, wait a few seconds (`browser_wait_for` with `time`) and scroll through it once (`browser_mouse_wheel`) before touching anything.
  - One field at a time, top to bottom, each in its own step: click into the field (`browser_click`), then type into it with `browser_type` and `slowly: true`. Never call `browser_type` without `slowly: true` (without it the value appears all at once), do not set values through `browser_evaluate`, and do not batch many fields into one call. Use `browser_evaluate` only to read the page.
  - Open dropdowns and pick options by clicking them. Use `browser_select_option` only for native `<select>` elements, after clicking the control.
  - To upload a file, click the upload control (`browser_click`) to open the file chooser, then call `browser_file_upload` with the exact absolute path.
  - After a file is chosen (by you or by `prefill`), take a snapshot before you judge the upload. Some sites hold the file until a dialog they open is finished: a privacy or data-use consent, a "parse my resume" confirmation, a crop or preview step. Finish it (a consent by the "Terms and consent checkboxes" rule below; it is usually a condition of uploading the resume), then check the upload again. An upload that still shows no file is a failure only once no such dialog is open.
  - Some portals rename the stored file (iCIMS shows `Resume` plus the date and time of upload, such as `Resume202610311049.pdf`). A filename other than the one you uploaded is not a failure by itself: the file is the approved resume when its timestamp matches an upload this application made, or the parsed profile matches the resume. Replace it only when it is plainly a different or older document.
  - Scroll with `browser_mouse_wheel` in moderate steps to bring things into view.
  - Your clicks and keystrokes are paced automatically, so each action takes a moment; that is intended. Never try to speed it up or work around it.
  - Type long answers in pieces of about 150 characters per `browser_type` call so no single call runs past its time limit. Before each later piece, click the field and press `End` (`Control+End` in a multi-line field) with `browser_press_key`: typing goes in at the caret, and a click can leave it mid-text. The field must hold the whole answer at the end. If a call does time out, check what the field holds before typing again.
  - If a typed value needs correcting, click the field, select its contents (`browser_press_key` with `Control+a`) and retype, rather than assigning the value.
  - Screenshots: `browser_take_screenshot` with `scale: "css"` (`fullPage: true` for a full-page one). For a challenge that needs clicks at a position, take a viewport screenshot and click with `browser_mouse_click_xy` at coordinates read from that latest screenshot.
